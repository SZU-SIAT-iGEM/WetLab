# DBTL Cycle 0：基于 asc 操纵子的质粒设计与工程菌构建

## Design｜设计

我们的项目希望解决微重力环境下弱传质导致的底物接触效率下降问题。由于液体对流显著减弱，纤维素降解后产生的可溶性糖难以快速扩散到远处，因此我们希望工程化大肠杆菌，使其能够感知并趋向纤维素降解产生的可溶性糖信号，从而主动靠近固体底物，提高局部接触和降解效率。

在第一轮设计中，我们选择了大肠杆菌自身基因组中存在的 `asc` 系统作为工程化对象。`asc` 操纵子与部分 β-葡萄糖苷类糖的转运和代谢有关，其中：

- `ascF` 编码与糖转运相关的膜蛋白；
- `ascB` 编码 β-葡萄糖苷酶，参与胞内后续代谢。

我们的目的是将目标基因（`ascF`、`ascB`）克隆至合适的表达载体，转化至大肠杆菌MG1655底盘，并获得可稳定传代、可诱导/组成型表达的工程菌株。

在质粒设计上，我们的主要设计决策点如下：

| 决策项        | 最终选择                     | 备注                                                                   |
| ---------- | ------------------------ | -------------------------------------------------------------------- |
| 底盘菌株       | *E. coli* MG1655         | 基因型：F- lambda- ilvG- rfb-50 rph-1                                    |
| 载体骨架       | pGEX-4T-1                | pBR322 ori（中低拷贝），单克隆位点，AmpR抗性                                        |
| 多克隆位点（MCS） | BamHI + EcoRI            | 使用 BamHI (GGATCC) 作为5'端插入位点，EcoRI (GAATTC) 作为3'端插入位点                 |
| 启动子        | J23116                   | 组成型启动子，无需诱导剂，强度约为参考启动子BBa_J23100的0.16倍，属于弱启动子                        |
| 终止子        | BBa_B0015                | 强双终止子，放置在最后一个基因的下游                                                   |
| RBS        | BBa_B0034                | 序列：AAAGAGGAGAAA，效率定义为1.0标准，每个CDS前各放置一个                               |
| 基因来源       | 野生型 *E. coli* MG1655 基因组 | 无密码子优化、无标签                                                           |
| 融合方式       | 双顺反子                     | [J23116] — [BBa_B0034] — [ascF] — [RBS_B0034] — [ascB] — [BBa_B0015] |
| 对照设计       | 空载体（EV）                  | 将终止子直接合成在载体内，同时作为空载对照                                                |

## Build｜构建

#### 引物设计

##### 1. 巢式 PCR 引物设计：从野生型 *E. coli* MG1655 基因组中提取`ascF`和`ascB`基因

- 从 NCBI 官网获取ascF 的序列、ascB 的序列和 *E. coli* MG1655 的全基因组序列

- 选取 ascF 和 ascB 上下游两端约 500bp 的碱基，使用 SnapGene 手动设计巢式PCR的两轮引物，Tm值为60℃

- 引物设计好后，用 NCBI 的 Primer-blast 功能检查引物的各项指标是否符合要求

##### 2. 无缝克隆引物设计：使用 Snapgene 中的 Gibson Assembly 组装质粒

- 由于 BBa_B0015 长度超过100bp，所以直接将其作为基因合成至载体 pGEX-4T-1 中，我们在基因合成产物的基础上进行Gibson组装

- 我们根据表达盒设计，将目标插入片段分为两段：
  
  Fragment 1：Promoter-RBS-ascF；Fragment 2：MidRBS-ascB

- 在 GibsonAssembly 页面插入所有片段后，点击产物页面，右上角选择重叠PCR引物，让SnapGene 自动设计同源臂

![](assets/2026-09-06-01-14-12-image.png)

- 共生成两对同源臂，加长第一对正向链引物让重叠区域覆盖到 ascF 上游，同时加长第二对正向链引物让重叠区域覆盖到 ascF 下游

![](assets/2026-09-06-01-14-39-image.png)

- 检查同源臂，质粒组装完成

##### 3. 测序引物设计：在组装好的质粒上设计测序引物

把表达盒分成四段，每一段之间有 20-30bp 重叠的碱基，给每一个片段分别设计引物

第一对引物：920_F, 1634_R

第二对引物：1587_F, 2483_R

第三对引物：2389_F, 3146_R

第四对引物：2483_F, 3920_R

## Learn｜学习

### Learn 1：质粒的成功构建并不代表表达可行性

我们将表达盒拆分为两个片段：Fragment 1（Promoter‑RBS‑ascF）和 Fragment 2（MidRBS‑ascB），通过 SnapGene 自动设计的同源臂进行 Gibson 组装。最终测序结果显示序列正确，说明两个片段之间的重叠区域设计合理，片段浓度比例也处于试剂盒推荐的摩尔比范围内。

然而，Gibson 组装和测序验证只能回答“片段是否按预期拼接”，而无法回答“拼接后的产物是否能有效表达”。真正决定翻译效率的是 RBS 与周围序列之间的相互作用，而这在序列拼接正确的结论中是被完全忽略的。

为了评估这一风险，我们在完成质粒设计后使用 RBS Calculator 对两个基因的翻译起始效率进行了预测。结果表明：在同一个转录本中，ascF 起始密码子（位置 990）的预测表达量仅为 1613.14，而 ascB 起始密码子的预测表达量则高达 5574.81。AscF 的表达量仅为 AscB 的 29%，前者比后者低了 3.5 倍之多。

![](assets/2026-09-06-01-22-13-image.png)

这一差异意味着两个基因共用同一个启动子，处于同一条 mRNA 上，使用完全相同的 RBS 序列（BBa_B0034），但仅仅因为 RBS 下游编码序列的前几十个碱基不同，即 mRNA 局部二级结构的差异，翻译起始效率就可能相差数倍。ascB 的 RBS 可能被其下游序列形成的茎环结构部分遮蔽，导致核糖体 30S 亚基的结合效率降低。

这意味着，即使我们使用了相同的 RBS，也不能假设两个基因会以相近的水平表达。当我们在 Cycle 1 中试图通过 SDS-PAGE 检测 AscF 和 AscB 时，如果其中一个基因的蛋白产物难以被检测到，这不一定意味着质粒丢失或转录失败，而可能仅仅是因为其翻译起始效率低于常规凝胶电泳的检测阈值。

更重要的是，这个差异的方向极具启发性：我们原本希望通过过表达 ascF 来增强纤维二糖的跨膜转运，但预测显示负责转运的膜蛋白 AscF 的翻译效率反而显著低于胞内酶 AscB。这意味着即使转录正常进行，到达膜上的转运蛋白数量也可能远低于预期，而胞内却积累了大量的 AscB 酶。如果纤维二糖转运本身就是限速步骤，那么 AscF 的低表达将直接导致底物进入胞内的通量不足，即便 AscB 表达再高也难以发挥作用，因为纤维二糖根本进不来。

RBS Calculator 的预测结果在 Cycle 0 的设计阶段就已经可用，但当时我们并未将其纳入设计评审的考量范围。直到 Cycle 1 的实验结果与预测趋势吻合后，回过头来审视才发现，这个信号原本是需要被重视的。如果我们最初就对 AscF 的 RBS 或基因起始区进行优化，而不是等到蛋白检测失败后才追溯原因，或许能够节省很多时间。

因此，在后续的工程迭代中，我们应当在设计阶段就将 RBS Calculator 预测作为质粒设计的常规检查项，而不是等到功能实验失败后才回头分析。如果预测显示负责限速步骤的关键蛋白（如转运蛋白）表达量偏低，我们可以在合成构建之前就通过调整 RBS 序列或优化基因起始区来加以平衡。

### Learn 2：本轮循环的成功有明确的边界条件

本轮实验完成后，我们可以肯定的是：目的基因已经成功导入工程菌，质粒也已经在底盘菌中稳定存在。

但我们还不能回答以下问题：AscF 和 AscB 是否在蛋白水平表达？表达量是多少？两个基因的表达是否均衡？工程菌是否因此获得了增强的纤维二糖转运能力或趋化表型？

这意味着 Cycle 0 的完成仅限于 DNA 构建层面。它为我们提供了可用于功能测试的工程菌株，但真正的功能验证需要下一轮实验来回答。

### 总结：Cycle 0 的核心贡献与遗留问题

综合来看，Cycle 0 在分子构建层面取得了明确成功：我们从基因组中成功扩增出 ascF 和 ascB，通过 Gibson 组装构建了序列正确的双顺反子表达盒，并建立了从 DH5α 克隆中间宿主到 MG1655 最终底盘的稳定转化流程。同时，我们建立的分段测序引物验证方案也为后续筛选提供了重要冗余，而 RBS Calculator 的预测结果则提前揭示了两个基因翻译效率可能存在显著差异，这一信息在后续 Cycle 1 中成为解释蛋白检测阴性结果的关键线索。

但与此同时，这一轮留下了几个关键问题尚未回答：蛋白是否表达、表达量是否足够、两个基因的表达是否均衡、膜蛋白是否正确定位，以及工程菌是否在功能上获得纤维二糖利用或趋化增益。这些正是 Cycle 1 需要直接面对的核心任务。

因此，Cycle 0 的结论为：我们成功构建了携带 ascFB 双顺反子表达盒的工程质粒，并将其稳定转入 *E. coli* MG1655。但该构建在蛋白表达水平和功能增益上的表现，有待 Cycle 1 进一步验证。RBS Calculator 的预测结果提示 ascF 的翻译效率可能显著低于 ascB，这为后续蛋白检测中可能出现的信号缺失提供了提前预警。这也直接引导我们进入下一轮的核心任务：从 DNA 构建走向功能验证，检测蛋白表达、测量纤维二糖利用能力、评估趋化响应，并根据结果决定是否需要对表达系统进行调整或替换。
